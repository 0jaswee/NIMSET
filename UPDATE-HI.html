नई website कैसे update करें

यह पूरी ZIP है। किसी पुरानी ZIP के साथ इसे मिलाने की जरूरत नहीं है। पहले से वेबसाइट है तो नीचे के चार कदम करें।

1. पहले अपना data बचाएँ

  1. पुराना tracker खोलें → Settings/Account → Export JSON। Backup अपने phone/computer में रखें; GitHub पर upload न करें।
  2. अगर Firebase पहले configure किया था, अपनी repository की firebase-config.js file download/copy करें। इसमें आपकी Web app config है। नई ZIP में यह default null है।
  3. Cloud इस्तेमाल कर रहे हैं तो sync पूरा होने दें। Update के समय tracker की बाकी tabs बंद करें।

2. Files replace करें

  1. नई ZIP extract करें। उसके अंदर index.html वाले level की files/folders आपकी repository के root में upload/replace करें। ZIP file खुद upload नहीं करनी है।
  2. firebase-config.js की अपनी configured copy रखें। नई ZIP से उसे replace कर दिया हो तो पुरानी saved values वापस डालें। Firebase project, Google provider और Firestore database/rules दोबारा बनाने की जरूरत नहीं।
  3. सबसे आसान: पूरी नई package की files replace करें। Repository/delete project करने की जरूरत नहीं; उसी repository और उसी GitHub Pages address का उपयोग करें। पुराने source-pdfs folder का app में अब उपयोग नहीं होता।
  4. Commit changes करें, फिर Pages deployment पूरा होने दें।

केवल बदली files upload करना चाहें तो: index.html, app.js, model.js, cloud.js, styles.css, sw.js, START-HERE-HI.html, UPDATE-HI.html, README.md, TEST-REPORT.md और tests/। Hash manifest INTEGRITY-SHA256.txt पूरे default package के लिए है; अपनी Firebase config बदलने पर उस file का hash स्वाभाविक रूप से अलग होगा। पूरा package replace करना अधिक आसान है।

3. नई website खोलें

  1. उसी GitHub Pages link को reload/reopen करें। पुराने buttons दिखें तो सामान्य reload या hard refresh करें। Service-worker cache version इस package में बढ़ाया गया है।
  2. Browser data/localStorage clear न करें। पहले वाला site address, topic IDs और storage keys नहीं बदले हैं; पुराना data उसी browser में मिलना चाहिए।
  3. यदि दूसरा browser/device है, वही Google account sign-in करें, या Account → Import JSON से backup लाएँ। Import पूरे current tracker को replace करता है—पहले current copy export करें।
  4. Firebase configured न हो तो app local mode बताएगा। सिर्फ sign-in होना सफल sync का प्रमाण नहीं; ऊपर का status देखें।

4. क्या बदला है

  • ऊपर केवल Home icon, सभी levels पर चलने वाला Search और light/dark toggle। Branding हटाई गई है।
  • Subjects में curriculum; Results में tests और actual study log; Account में Google sign-in/Logout, preferences और backup। नीचे बीच में Home है।
  • Topic का नाम खोलने पर उसी app में ऊपर वही topic और नीचे केवल उसके direct subtopics दिखते हैं। Back और पूरा clickable path ऊपर हैं।
  • हर row में More: Description और Notes & Links उसी के पास खुलते हैं। Edit Details से title, description और exam relevance सीधे text में edit होते हैं। Save/Cancel वहीं हैं; popup नहीं।
  • Copy Link वहीं है। + Add Subtopic अब Subtopics heading के पास है—हर level पर। Notes और resource links topic के अपने हैं।
  • Parent complete तभी होगा जब सभी descendants complete हों। किसी child को अधूरा करने/नया child जोड़ने से parent फिर अधूरा होगा। पुराने inconsistent parent ticks ठीक होंगे; notes, links और completed leaf topics नहीं मिटेंगे।
  • Weekly Planner: Monday–Sunday, Week 1/2/3, दिन के पास + Task, inline Edit, dates और planned minutes, backlog। Actual study minutes अलग log होती हैं। Week 1 का Monday Account preferences में बदल सकते हैं; existing task dates नहीं बदलते।
  • Unsaved edits रहते हुए navigation और cloud replacement रुकेंगे; पहले Save या Cancel करें। Keyboard: Ctrl/⌘ + Enter से details Save, Esc से Cancel।
