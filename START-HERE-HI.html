पहले से website upload है? यह छोटी update guide पहले पढ़ें।

पहले website upload करें। बिना Firebase के भी सभी study features local mode में चलेंगे। बाद में private sync जोड़ सकते हैं। कोई build, MySQL, Hostinger या paid server जरूरी नहीं।

1. ZIP से GitHub Pages तक

  1. ZIP extract करें। इसमें index.html वाली folder के अंदर की सभी files/folders upload करनी हैं; पूरी ZIP को repository में रखने से website नहीं खुलेगी।
  2. GitHub में अपना repository खोलें। Free plan पर public repository उपयोग करें। Add file → Upload files चुनें। index.html, JS/CSS, manifest, icons, guide, topics और app files सहित सारी सामग्री उसी level पर रखें। फिर Commit changes करें।
  3. Repository → Settings → Pages → Build and deployment → Source: Deploy from a branch। Branch: main (या अपनी branch), folder: /(root) → Save।
  4. Deployment पूरा होने पर Pages में दिया URL खोलें, जैसे https://YOUR-USERNAME.github.io/YOUR-REPO/। Link के अंत का slash रखें। कुछ समय लग सकता है; Actions में build/deploy status देखें।
  5. पुरानी site update करने से पहले Export JSON करें। नई ZIP की app files उसी repository में replace करें। firebase-config.js में अपनी मौजूदा config रखें। फिर deployment पूरा होने पर reload करें। पुराने code की local storage keys और topic IDs नहीं बदले हैं। सीधा index.html double-click करके file:// से न चलाएँ; modules और fetch को HTTP/HTTPS चाहिए। Local test के लिए folder में Python हो तो python -m http.server 8080, फिर http://localhost:8080/ खोलें।

Code और topic सूची सार्वजनिक website पर उपलब्ध होंगे। इस English edition में original timetable PDFs शामिल नहीं हैं और teachers के नाम हटाए गए हैं। अपना exported backup या निजी notes GitHub में upload न करें। GitHub की official गाइड ↗

2. Local mode और Google sign-in का अंतर

पहली बार पूरा tracker आपके browser में चलता है। Notes, links, checkboxes, tests और plans इसी browser/origin की localStorage में रहते हैं। Incognito या browser data clear करने पर data खो सकता है। हर सप्ताह Account → Export JSON करें।

दूसरे phone/computer पर private per-user sync के लिए sign-in चाहिए। Google account की पहचान से rules सिर्फ आपका document पढ़ने/लिखने देते हैं। बिना पहचान के सबको read/write देने वाले Firestore rules असुरक्षित हैं। यह app ऐसा नहीं करता। Firebase config खाली होने पर app साफ “Local only” दिखाता है।

Demo data और हर Google account का local data अलग है। Demo से शुरू किया है तो पहले Export JSON, फिर sign-in, फिर Import JSON करें। उसी Google account से दूसरे device में खोलें। दूसरी Google ID चुनने पर अलग study space मिलेगा।

3. Free Firebase project बनाएँ

  1. Firebase Console खोलें → Add/Create project → कोई नाम दें, जैसे nimcet-study-2027। Analytics इस tracker के लिए आवश्यक नहीं; बंद रख सकते हैं।
  2. Spark/free plan रखें। App को Firebase Storage, Functions या billing upgrade की जरूरत नहीं है। Photos/PDF upload करने की बजाय अपने Drive links जोड़ें। Free quota सीमित है; Firebase Console में usage देखें।
  3. Project settings (gear) → General → Your apps → Web </> → nickname दें। Firebase Hosting अभी जरूरी नहीं, क्योंकि website GitHub Pages पर है।
  4. दिखने वाले firebaseConfig object के values copy करें। केवल Web app config लें; service-account JSON, Admin SDK private key, Google password या OAuth client secret कभी website में न डालें।

4. Google Authentication चालू करें

  1. Firebase Console → Build/Security → Authentication → Get started → Sign-in method/providers → Google → Enable। Support email चुनें → Save।
  2. Authentication → Settings → Authorized domains → Add domain में YOUR-USERNAME.github.io जोड़ें। https://, slash या repository path नहीं डालना है। Custom domain उपयोग हो तो उसका hostname भी जोड़ें।
  3. Local testing के लिए जरूरत हो तो localhost और 127.0.0.1 manually जोड़ें। Console में मौजूद domains जाँचें; localhost अपने आप मौजूद मानकर न चलें।
  4. यह app Google popup sign-in इस्तेमाल करता है। Phone पर popup block हो तो उस site के popups allow करें और सामान्य Chrome/Safari में खोलें; किसी दूसरे app के embedded browser में नहीं। Desktop पर sign-in करके भी जाँच सकते हैं।

Google की screen में अपना account चुनें। Same account दोनों devices पर जरूरी है। Official Google sign-in guide ↗

5. Firestore database और सुरक्षा rules

  1. Build → Firestore Database → Create database। Standard edition और Production mode चुनें। अगर interface अलग हो तो default database (default) बनाएँ।
  2. Location सोचकर चुनें; आपके करीब उपलब्ध region ठीक है। Database बन जाने पर location आसानी से बदलती नहीं।
  3. Firestore → Rules tab खोलें। ZIP की firestore.rules file का पूरा content paste करें → Publish। Test mode में सबको access देने वाले नियम न रखें।
  4. App अपने आप यह document बनाता है: users / GOOGLE_UID / tracker / main। पहले से collection बनाने की जरूरत नहीं।

नियमों में request.auth.uid == userId के कारण केवल उसी user का document accessible है। Payload, revision और server timestamp भी जाँचे जाते हैं। कोई public collection/query इस्तेमाल नहीं होती। JSON payload की आंतरिक study fields client पर validate होती हैं; rules उसे opaque string मानते हैं। Official rules guidance ↗

6. Website में config भरें

Repository में firebase-config.js खोलें → pencil/Edit। मौजूदा export const firebaseConfig = null; को अपने values वाले object से बदलें। एक ही active export रखें:

export const firebaseConfig = {
  apiKey: "अपनी-Web-app-apiKey",
  authDomain: "अपना-project.firebaseapp.com",
  projectId: "अपना-project-id",
  appId: "अपना-Web-app-appId"
};

ऊपर के उदाहरण को ज्यों-का-त्यों न रखें। अपने Console से exact values लें। Web configuration public client पहचान है; वह Admin secret नहीं। निजी data की सुरक्षा Authentication और प्रकाशित Firestore rules से होती है। Firebase का CDN SDK version pinned है; app को कोई build command नहीं चाहिए।

Commit changes करें। GitHub Pages deployment के बाद refresh करें। पुरानी config दिखे तो सामान्य browser में refresh/website reopen करें; जरूरत हो तो browser site settings से service worker update करें। Local data clear करने से पहले JSON export करें।

7. दोनों devices से sync जाँचें

  1. Tracker → Account → Google sign-in। Rules और config सही हों तो किसी topic में छोटा note लिखें। ऊपर status में Synced आने दें। केवल Google login होना sync होने का प्रमाण नहीं।
  2. दूसरे device में वही GitHub Pages URL और वही Google account खोलें। वही note दिखना चाहिए। वहाँ completion बदलें; पहले device पर बदलाव दिखना चाहिए।
  3. Internet बंद करके बदलाव करें। Status local/pending होगा। Internet लौटने पर Retry sync करें। Failed write को app “Synced” नहीं कहता। App का local mode offline चलता है; Firestore transactions के लिए online रहना जरूरी है।
  4. दो devices पर एक साथ अलग बदलाव होने पर conflict आएगा। Account फिर खोलें। दोनों devices से export करें, फिर Cloud version या Local version चुनें। यह whole-tracker version choice है, automatic field merge नहीं। Local चुनने से cloud का दूसरा version replace होगा।

एक browser में एक tracker tab रखें। दूसरे tab में बदलाव होने पर app export/reload करने को कहता है। Free quota के लिए writes debounce की गई हैं; हर save में एक compact private document जाता है। Data 800 KB से बड़ा होने पर app आगे save/import reject करेगा; पुराने logs/बड़े notes backup करके कम करें। Binary/photo content JSON में नहीं रखें।

8. रोज उपयोग कैसे करें?

  • Subjects: किसी subject → unit → lecture में जाएँ। एक screen पर केवल direct subtopics दिखेंगे। Row का More दबाएँ: Description और Notes & Links दो tabs वहीं खुलेंगे। Edit Details से title/description/relevance उसी जगह बदलें और Save/Cancel करें। + Add Subtopic उसी heading के पास है; ऊपर Back और पूरा path है। PDF lecture का मूल title और source reference अलग दिखता है। Teachers के नाम नहीं दिखते। हर स्तर पर Edit, + Subtopic, Notes और कई resource links हैं।
  • Completion: हर node अपना checkbox रखता है। Progress में स्वयं और उसके सभी descendants गिने जाते हैं। Parent तभी tick होगा जब सभी descendants पूरे हों। किसी child का tick हटाने या नया अधूरा child जोड़ने से ancestors के ticks हटेंगे। पुराने backup में inconsistent parent tick हुआ तो केवल वह parent दोबारा अधूरा होगा; completed leaves और notes नहीं मिटेंगे। यह संख्या workload/lecture hours का weighted प्रतिशत नहीं है।
  • Search: topic, parent path, notes या date खोजें। Result पर क्लिक सीधे उसी detail पर ले जाएगा। Copy direct link से hash URL share/bookmark कर सकते हैं। निजी custom topic दूसरे व्यक्ति के account में मौजूद नहीं होगा।
  • Planner: Week 1/2/3 या तारीख चुनें। Monday–Sunday की सूची में हर दिन के पास + Task है; Add/Edit उसी दिन inline खुलेगा। Week 1 का Monday Account preferences में बदल सकते हैं। 150-minute starter plan चुने दिन पर जुड़ता है। पुरानी incomplete tasks Backlog में दिखती हैं; Edit से नया दिन दें। Study minutes अलग log करें; planned minutes को actual पढ़ाई नहीं माना जाता।
  • Results: test net marks और maximum marks दें। Mistakes लिखें। Chart प्रतिशत दिखाता है, कोई rank predictor नहीं। Negative net score भी log कर सकते हैं।
  • Account: provisional date, daily minutes, backup और sync। Dark/light button ऊपर है। Default 31 मई 2027 planning milestone है; official exam date नहीं।
  • Photo/PDF: अपनी file Google Drive में डालें और जरूरी share permission देकर उसका link जोड़ें। इस app में file upload/storage feature नहीं है।

9. Curriculum के बारे में सही अपेक्षा

पाँच supplied lecture planners में 389 lectures: Mathematics 202, Reasoning 55, Computer 66, English Grammar 26, Quantitative Aptitude 40। Topic सूची और per-page extraction audit साथ हैं; मूल timetable PDFs ZIP में नहीं हैं। Mathematics का तीसरा पेज [1] Recorded footnote है। Unit capitalization variants और duplicate practice titles हटाए नहीं गए हैं। एक overflowing Mathematics row को adjoining cells से recover किया गया; record में note दिया है।

Topic descriptions, study priorities, daily split और question styles हमारे जोड़े गए अध्ययन सुझाव हैं। ये PDF का verbatim भाग या verified previous-year question analysis नहीं हैं। कोई निश्चित chapter-wise weightage नहीं दिया गया। User edit बचे हुए source references को नहीं बदलता। Delete से source-records.json नहीं मिटती; नई installation में baseline curriculum मौजूद रहता है।

Official revised syllabus (2026 onwards) से 2027 brochure आने पर मिलान करें। Logic/truth tables, moments/frequency distributions और English technical writing/word formation की coverage विशेष रूप से जाँचें। DBMS, programming, differential equations जैसे कुछ planner topics official 2026 सूची में अलग नाम से नहीं हैं; उन्हें extension कहकर रखा है। Quantitative Aptitude अलग official section नहीं। BIT Mesra backup के लिए संस्थान की admission प्रक्रिया अलग से verify करें।

10. समस्या आए तो

  • auth/unauthorized-domain: GitHub hostname Authorized domains में जोड़ें।
  • auth/operation-not-allowed: Google provider enable करें। auth/popup-blocked: popup allow करें।
  • permission-denied: सही project में rules publish किए हैं और account signed in है, जाँचें।
  • unavailable / offline / quota: internet और Firestore usage जाँचें; local backup लें और Retry sync करें।
  • Blank page: ZIP extract करके index.html repo root में upload है या नहीं देखें; filename case न बदलें। HTTP/HTTPS से खोलें।
  • Local data full: JSON export करें, लंबे notes/पुराने logs कम करें। Failure के बाद current tab बंद करने से पहले export करें।
  • New version: पहले Export JSON; source files update करें। sw.js का CACHE version बढ़ाएँ जब offline shell files बदलें।
